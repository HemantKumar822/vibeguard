# Epic 5 Context: Demonstrate the complete workflow with repeatable evidence

## Goal

Establish a repeatable, measured demonstration of all required modes on the actual machine. Evaluation must disclose misses, failed checks, unsupported cells and fixture-only boundaries rather than presenting planning or mocked output as completion.

## Stories

- Story 5.1: Run the labeled acceptance and adversarial corpus
- Story 5.2: Verify accessible recovery and rehearse the honest demo

## Requirements & Constraints

Evaluate vulnerable, corrected and clean controls for credentials, unsafe input, insecure configuration and access-check candidates. Source and repository validate selected static rules; website cases validate actual passive alerts and browser-visible fake credentials. Public browser keys must remain controls. A missing local check is not proof of an authorization bypass. Unsupported website categories must be explicit, not inflated coverage.

Use issue occurrences as the scoring unit, deduplicating overlapping reports. Record TP/FP/FN with their denominators, expected and observed locations/rules, policy/tool/rule versions, coverage and measured runtime. Omit precision or recall with zero denominators; incomplete checks must not improve metrics by removing missed labels. Assess correct location, understandable impact, actionable change, verification and human credential actions separately. Do not fabricate teammate judgments or speed claims.

Fake planted values must be absent from persisted reports, logs, provider input, UI, clipboard and exports. Never execute submitted source, install its dependencies or follow its scanner settings. Test hostile paths, archives, resource bounds, redirects/DNS, ownership, CSRF, retries, deletion/crashes, malformed vendor output, model outages and comparison uncertainty. Failure is a release blocker, not another successful input mode.

## Technical Decisions

Use the established same-origin API, core-owned SQLite queue and trusted host coordinator with pinned restricted workers. Source and website networking remain separate. Keep all raw runtime data outside Git and OneDrive and publish sanitized evidence only. Preserve permission/opt-in, tombstones, late-write fences, deadlines and cleanup semantics. Controlled transport fixtures and live public transport are distinct evidence classes; fixture adapters cannot become a production policy bypass. Actual scanners must produce the observations in both classes.

## UX & Interaction Patterns

Exercise submit/investigate/repair and real rescan/compare journeys in the rendered application. Check desktop, 360px, 200% zoom, keyboard focus/order, text labels, announcements, contrast, independent evidence scrolling and reduced motion. Visual tokens alone are not an accessibility pass. Preserve reports and selection across errors and deliberate reconnects. Polling or refresh must not dispatch duplicate jobs. Error, partial, denied, expired, empty-filter, clean, unavailable clipboard/folder and failed deletion states require clear recovery. Deletion defaults focus to Cancel; narrow evidence selection provides a Back action. Copy success/failure is announced and sanitized manual copy remains available.

## Cross-Story Dependencies

Epic 4 supplies the comparison workflow. Story 5.1 establishes measured corpus and safety evidence; story 5.2 consumes it for recovery/accessibility fixes and a clean-start rehearsal. Full epic completion requires actual successful required-mode loops plus honest unresolved-limit disclosure, not just a runnable harness.
